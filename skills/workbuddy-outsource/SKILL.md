# 外包给 WorkBuddy（花鸡蛋，不烧 token）

## 一句话模型

WorkBuddy CLI **本身就是一个 agent**（自带工具、自己的会话），所以对接方式跟 DSH 的 `subagent` 工具**同构**：

```
本鲸写一份自包含任务书 → WorkBuddy 在自己上下文里干活 → 产物落本地
→ 本鲸核对「改了什么」→ 体检 + 真机验证 → 通过才搬进正主目录
```

**它不是聊天模型**，看不到本会话的上下文 —— 所以任务书必须**自包含**，这是外包质量的分水岭。

## 外包口径（2026-10-13 放宽：主人积分充裕，**默认外包**）,,**默认外包，例外才自己干。**,,| 默认外包 ✅ | 自己干（例外）❌ |,|---|---|,| 写/改代码、批量改造、重构、搬砖式重命名替换 | 需要**本会话对话上下文 / 主人偏好**的判断 |,| 写文档/README/注释、数据清洗、生成测试与模板 | 涉及**密钥 / 凭据 / 隐私文件** |,| 独立小工具、独立脚本、把某目录按规范重构 | **必须在真机验证**（重启 DSH、看界面、跑 GUI） |,| 任何"说清要求、它照做"的自包含活 | 任务书 + 验证的成本**高于**直接做完（改一行、回一句话） |,,**带上下文不再算难题**：用 `--include` 把相关文件/目录拷进沙箱让它就地读 —— **别把大段代码粘进任务书**。,,**硬规则（不变）**：产物先落沙箱 → 体检（`node --check` / 变更清单 / 试跑）→ 才搬进正主；改 `profiles` / `~/.dsh` 先备份、在沙箱里改好再搬。,
## 怎么跑

```bash
WB=<插件目录>/tools/wb.mjs   # 真实路径以 system prompt 里给的那条为准（插件按存在性回退：自带 tools/ → $DSH_HOME/tools/），别写死
node "$WB" --check                                     # 先看 CLI 在不在、登录没登录
node "$WB" "任务描述" --name 任务标签                    # 自动建工作目录
node "$WB" --brief 任务书.md --dir /path/to/copy
node "$WB" "按 specs/规范.md 重构 lib/" --dir /tmp/job --include src/lib --include specs
```

常用参数：

| 参数 | 作用 | 默认 |
|---|---|---|
| `--dir <目录>` | 工作目录（**建议先复制一份**，别指向正主目录） | 新建 `<DSH 家目录>/wb-outsource/<时间戳>-<标签>` |
| `--model <id>` | 模型 | `deepseek-v4.1-flash` |
| `--context <文件>` |
| `--include <路径>` | **把文件/目录拷进工作目录**（可重复）—— 给上下文的正道 | 无 |
| `--turns <n>` | agent 最大轮数 | 40 |
| `--timeout <秒>` | 超时（到点强杀，产物仍在） | 900 |
| `--allow-bash` | 放开 Bash（默认**禁止**，只让它读写文件） | 关 |

产物：`workDir` 里的文件 + 日志与 `run.json` 在 `<DSH 家目录>/wb-outsource/_runs/<时间戳>/`。

## 任务书怎么写（关键，占外包质量的 8 成）

模板：

```
【目标】一句话说清要什么
【输入】目录里已有哪些文件、从哪个文件抄风格（给具体文件名）
【输出】要新建/修改哪些文件；每个文件的职责
【约束】语言/依赖（不许引入新库）、命名规范、注释要求
【验收】我会怎么检查（比如：必须能被 node --check 过、必须有 --help）
```

⚠️ **先复制再外包**：把要改的东西复制到 `<DSH 家目录>/wb-outsource/<任务>/` 再让它动手 —— 这样"它改坏了"的代价是零。

## 验证门（不许跳过）

外包产物**一律视为草稿**。搬进 DSH 之前必须过：

1. `node --check <每个 .js/.mjs>` —— 语法
2. 读一遍 `run.json` 的 `changes` —— 确认它**只动了预期文件**（动了别的东西当场回退）
3. 检查**是否引入新依赖 / 联网调用 / 写死路径**
4. 在 `wb-outsource` 里先**试跑**（脚本要出 `--help`、产物要能解析）
5. 涉及 DSH 插件的：走离线断言 + `cordis.patch.yml` 冒烟
6. 才复制进正主目录；**改官方端 profile 前先备份 + 记快照**

## 故障排查

| 症状 | 原因 / 处理 |
|---|---|
| `Authentication required. Please use /login` | **CLI 没登录**（它**不共享桌面端登录态**）。终端跑 `codebuddy` → 输 `/login` |
| 退出码 4 `NOT_FOUND_CLI` | 用 `WB_CLI=<路径>` 指定；一般在 `%LOCALAPPDATA%\Programs\WorkBuddy\resources\app.asar.unpacked\cli\bin\codebuddy` |
| 模型被拒（报不支持） | `--model auto` 试；CLI 帮助里的模型清单**与桌面端产品配置不一致**，以实测为准 |
| 退出码 2 超时 | 拆小任务，或加大 `--timeout`；产物还在 `workDir` |
| 什么都没改 | 看 `run.json.result` —— 多半任务书太模糊，或它只回答没动手 |

## 与外包模式开关（🥚 插件）的关系

- 开关是输入框右侧的 **🥚 按钮**（底部状态栏那一行显示本会话外包次数）。开启后**本会话**默认尽量把重活往外推 —— 开关状态会以"系统提示词"条目的形式**可见地**出现在对话里（不搞隐形注入）。
- **只对当前会话生效**：注入按会话判定，开 A 会话不会管到 B 会话；没开的会话拿到的是空串。
- **纯内存、重启归零**：重启 DSH（= 新进程）后所有会话都回到「关」，要重新点一下才生效。
- 想一次性清空**全部**会话的开关，调 `POST /api/dsh-wb-outsource/reset`。
- 旧文件 `~/.dsh/outsource-state.json`（旧的全局粘性开关）**已退役**，插件不再读写它。

⚠️ **外包 ≠ 免费**：花的是 WorkBuddy 积分（只是主人觉得花不完）。所以别拿它干"一句话就能做的事" —— 写任务书 + 验证的成本比自己做还高。
